# /simplify - "Simple is Best" 코드 리팩토링 스킬

## 목적
프로젝트 코드를 분석하여 "Simple is Best" 철학에 따라 복잡성을 줄이고 가독성을 높이는 리팩토링을 수행합니다.

## 분석 대상
$ARGUMENTS 인자가 제공되면 해당 파일/디렉토리만 분석합니다. 인자가 없으면 사용자에게 분석 범위를 물어봅니다.

## 실행 지침

### 1단계: 코드 분석
분석 대상 코드를 탐색하여 다음 항목을 검토합니다:

**복잡도 분석**
- 깊은 중첩 (3단계 이상의 if/for/while)
- 긴 메서드 (30줄 이상)
- 과도한 매개변수 (4개 이상)
- 복잡한 조건식

**중복 분석**
- 유사한 코드 블록
- 반복되는 패턴
- 복사-붙여넣기로 보이는 코드

**불필요한 복잡성**
- 사용하지 않는 변수/메서드/클래스
- 과도한 추상화 (인터페이스, 베이스 클래스)
- 불필요한 디자인 패턴 적용
- 죽은 코드 (도달 불가능한 코드)

### 2단계: 문제점 보고
발견된 문제를 우선순위별로 정리합니다:
- 🔴 **높음**: 즉시 수정 필요 (버그 위험, 유지보수 불가)
- 🟡 **중간**: 개선 권장 (가독성 저하, 중복)
- 🟢 **낮음**: 선택적 개선 (스타일, 미세 최적화)

### 3단계: 리팩토링 원칙 적용

다음 KISS 원칙을 따릅니다:

1. **단순함 우선**: 복잡한 해결책보다 단순한 해결책 선택
2. **불필요한 추상화 제거**: 한 번만 사용되는 인터페이스/베이스 클래스 제거
3. **중복 코드 통합**: DRY 원칙이지만 과도한 추상화 없이
4. **조건문 단순화**: Guard clause 패턴, 조기 반환 활용
5. **사용하지 않는 코드 삭제**: 주석 처리된 코드, 미사용 변수 제거
6. **명확한 네이밍**: 코드 자체가 문서가 되도록

### 4단계: 개선안 제시 및 적용

각 문제에 대해:
1. **현재 코드** 보여주기
2. **문제점** 설명
3. **개선된 코드** 제시
4. 사용자 승인 후 적용

## 출력 형식

```
## 📊 분석 결과 요약

### 분석 범위
- 파일 수: N개
- 총 라인 수: N줄

### 발견된 문제
- 🔴 높음: N개
- 🟡 중간: N개
- 🟢 낮음: N개

---

## 🔍 상세 분석

### [파일명:라인번호] 문제 제목

**현재 코드:**
\`\`\`csharp
// 문제가 있는 코드
\`\`\`

**문제점:** 설명

**개선안:**
\`\`\`csharp
// 개선된 코드
\`\`\`

---

## ✅ 권장 작업 순서
1. [가장 중요한 변경]
2. [두 번째 변경]
...
```

## 주의사항
- 기능 변경 없이 구조만 개선 (리팩토링 원칙)
- 테스트가 있다면 테스트 통과 확인
- Unity 특수 패턴 (MonoBehaviour 라이프사이클 등) 존중
- 팀 컨벤션이 있다면 준수

## 예시 명령어
- `/simplify` - 분석 범위 질문
- `/simplify Assets/Scripts/Error/` - Error 폴더만 분석
- `/simplify Assets/Scripts/IPCReceiver.cs` - 특정 파일만 분석
